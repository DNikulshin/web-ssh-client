## Как поднять локально

```bash
cd ~/projects/web-ssh-client
pnpm install && cp .env.example .env
node --watch src/index.ts          # http://127.0.0.1:3000, первый вход — регистрация владельца
node tools/verify.mjs              # типы + тесты
node src/hub/cli.ts status         # что реально живёт: pid, сокет, статус
```

Демо без реальных хостов: `WEB_SSH_FAKE_SESSIONS=true WEB_SSH_DATA_DIR=/tmp/wssh-demo node src/index.ts`.

Реальный SSH (на этой машине уже работает локальный sshd на 22):

```bash
WEB_SSH_TEST_HOST=127.0.0.1 WEB_SSH_TEST_USER=$USER WEB_SSH_TEST_KEY=~/.ssh/webssh-test \
  node --test test/real-ssh.test.ts
```

## Что осталось на машине

- `~/.ssh/webssh-test` + `.pub` — тестовый ключ для гейтед-теста.
- одна строка в `~/.ssh/authorized_keys` с пометкой `web-ssh-client integration test`.
  Убрать: `sed -i '/web-ssh-client integration test/d' ~/.ssh/authorized_keys`.
- `.env` не создавался, данные сервиса — только во временных каталогах, они удалены.

## Следующие шаги (в порядке предложенного)

1. **Поле «команда запуска сессии» у хоста + tmux-resume (ADR-006).** Сейчас после перезагрузки
   *хоста* сессия честно помечается `lost`. С `tmux new -A -s webssh` вместо голого `shell` она
   переподключается к тому же tmux. Заодно даёт явный выбор оболочки (в том числе `pwsh`) вместо
   реестровой настройки `DefaultShell` на Windows-хостах.
2. **`known_hosts` (ADR-007).** Сейчас ключ хоста не сверяется — для недоверенных сетей не годится.
   Нужен источник правды (TOFU + БД) и UI подтверждения нового ключа.
3. **Автотест на WS-прокси.** REST покрыт, сам прокси кадров проверен только руками.
4. **Ограничение частоты входов и TOTP.** Сейчас rate limit предполагается на прокси.
5. **Ретенция истории** — логика удаления старых чанков по `WEB_SSH_SCROLLBACK_BYTES` без теста.
6. **Деплой — остался один шаг от root.** Всё готово и проверено, кроме самой установки:
   `deploy/make-release.sh` (архив с прод-зависимостями) + `deploy/install-host.sh`
   (пользователь `webssh`, `/opt/web-ssh`, `/var/lib/web-ssh`, юнит с `KillMode=process`,
   nginx `ssh.dnikulshin.ru` → `127.0.0.1:3030`), плюс `docs/deploy.md`. Ставит владелец:
   агент root-команд не имеет. После установки: регистрация владельца и сразу
   `WEB_SSH_ALLOW_REGISTRATION=false`.

## Открытые вопросы к владельцу

- Дизайн: палитра GitHub-dark сохранена как «как в текущей системе». Если имелся в виду другой
  референс (`pc-remote`, `hair-lab`) — перерисовывать.
- SQLite вместо Postgres: годится для одного пользователя на одном хосте. Если сервис должен
  стать многопользовательским/многохостовым — решать сейчас, а не после первого пользователя.
- Нужен ли разделённый экран (две консоли рядом) — в макете вопрос оставлен открытым.
- **basic-auth перед сервисом** (`deploy/nginx/ssh.dnikulshin.ru.conf`) включён как второй
  замок, пока в приложении нет TOTP и rate limit. Убирать — вместе с пунктом 4, не раньше.
