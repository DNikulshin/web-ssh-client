# Проверки

Одна команда — все проверки:

```bash
node tools/verify.mjs
```

Порядок намеренный: сначала дешёвая статика (`tsc --noEmit`), потом тесты, которые
поднимают процессы. Упавший тип не должен ждать, пока отработают интеграционные тесты.

## Что проверяется

| файл | о чём | почему именно так |
| --- | --- | --- |
| `test/vault.test.ts` | конверт AES-GCM: roundtrip, подмена aad, подмена шифротекста, версия ключа, права 0600, испорченный файл ключа | «креды в БД» — это про то, что утечка БД не даёт доступ; проверяется отрицательными сценариями |
| `test/frames.test.ts` | кадры: разрезанный по байту поток, бинарный вывод, несколько кадров в чанке, предел длины, неизвестный тип | сокет не обязан отдавать кадр целиком; ошибка здесь выглядит как «терминал иногда показывает мусор» |
| `test/session-resilience.test.ts` | отключение клиента → `detached`; повторный `attach` → replay; `SIGKILL` воркера → чанки на диске; `reconcile` → `lost` | это главное обещание сервиса; тест воспроизводит именно те отказы, от которых он должен защищать |
| `test/nginx-proxy.test.ts` | настоящий nginx с боевым конфигом: 401 без basic-auth, заголовки, REST и **реальный `wss://`** с кадрами терминала | `fastify.inject` не умеет upgrade; «форма входа работает, терминал молчит» ловится только живым прокси |

Фейковый транспорт: воркер с `--fake` не подключается никуда, эмитит `[fake] tick` и отражает
ввод как `[fake-echo] …`. Поэтому тесты не требуют ни SSH-сервера, ни сети, ни кредов.

## Как воспроизвести тест на выживание вручную

```bash
export WEB_SSH_DATA_DIR=/tmp/wssh-manual
node -e "
const {openAndMigrate}=await import('./src/db/index.ts');
const db=openAndMigrate('/tmp/wssh-manual/web-ssh.db');
db.prepare('INSERT INTO users (id,login,password_hash,created_at) VALUES (?,?,?,?)').run('u','t','x',Date.now());
db.prepare('INSERT INTO sessions (id,user_id,host_id,title,status,created_at) VALUES (?,?,NULL,?,?,?)').run('s1','u','manual','starting',Date.now());
" --input-type=module

node src/hub/worker.ts s1 /tmp/wssh-manual/s.sock --fake &
sleep 1
node src/hub/cli.ts status          # сокет и pid живы
kill -9 <pid воркера>
node src/hub/cli.ts reconcile       # сессия → lost
```

Историю вывода после `SIGKILL` смотреть так:

```bash
sqlite3 /tmp/wssh-manual/web-ssh.db \
  "SELECT seq, LENGTH(data) FROM session_chunks WHERE session_id='s1' ORDER BY seq;"
```

## Реальный SSH (включается окружением)

Единственный тест, который ходит по сети, — `test/real-ssh.test.ts`. Он пропускается, пока не
заданы переменные, а не «проходит» на фейке:

```bash
WEB_SSH_TEST_HOST=127.0.0.1 \
WEB_SSH_TEST_USER=dev \
WEB_SSH_TEST_KEY=~/.ssh/webssh-test \
node --test test/real-ssh.test.ts
```

Что проверяет: вход по ключу (кред расшифровывается из БД и уходит в `ssh2` как `privateKey`),
запрос `shell` с `TERM=xterm-256color`, дохождение размера pty до удалённой стороны
(`stty size` = заданные rows/cols, то есть `setWindow` работает), проброс кода выхода
(`exit 3` → кадр `exit` в клиент и `exit_code` в БД), запись вывода в `session_chunks`.

Прогон 24.11.2026 на этой машине (Ubuntu 26.04, локальный `openssh-server` на 22-м порту,
пользователь `dev`, ключ `~/.ssh/webssh-test` добавлен в `~/.ssh/authorized_keys`): 1 тест,
2.2 с, всё перечисленное подтверждено.

Первый прогон теста сразу нашёл дефект: ввод, отправленный до готовности shell (SSH-хендшейк
занимает секунды), молча терялся — теперь воркер буферизует до 64 КиБ ввода и отдаёт его,
как только канал открыт.

## Интерфейс: как проверялось руками

Веб-слой без реального SSH поднимается так:

```bash
WEB_SSH_FAKE_SESSIONS=true WEB_SSH_DATA_DIR=/tmp/wssh-demo WEB_SSH_PORT=3113 node src/index.ts
```

Что проверено в браузере (Playwright, скриншоты — `artifacts/shots/`):

1. первый запуск → создание владельца → вход;
2. добавление креда и хоста через ⚙, хост появляется в рельсе;
3. клик по хосту → новая сессия → `[fake] tick N` в терминале, ввод возвращается эхом;
4. вторая консоль к тому же хосту → две вкладки, разные сессии (`fake-prod`, `fake-prod #2`);
5. закрытие вкладки → сессия остаётся `detached` в рельсе;
6. F5 → вкладки и активная сессия восстановлены, история подтянута из БД (`hist N`);
7. `kill -9` веб-слоя → воркер жив (`detached`), после старта сервиса клиент сам
   переподключился, счётчик тиков продолжился (та же сессия, не новая);
8. мобильный вид 390×844: drawer по ☰, панель клавиш, safe-area.

Автоматизировать это в CI можно тем же Playwright — пока шаги ручные, поэтому в `verify.mjs`
их нет: не выдаём ручную проверку за автоматическую.

## nginx и WebSocket

`test/nginx-proxy.test.ts` берёт **боевой** файл `deploy/nginx/ssh.dnikulshin.ru.conf` и
подменяет в нём только машинное: порт, сертификат и файл basic-auth. Значит, проверяется
ровно тот конфиг, который поедет на хост. Тест пропускается (а не «проходит»), если в `PATH`
нет `nginx` или `openssl`.

Что он подтверждает: upgrade-локация `/ws/` действительно пропускает кадры (`[fake] tick`
приходит через `wss://`), `X-Frame-Options`/`no-store` на месте, `limit_req` не мешает
обычной работе, секрет кредов не появляется в ответах и через прокси.

## Чего тесты не покрывают (и это надо знать)

- **Настоящий SSH.** Ни один тест не подключается по сети: нужен реальный хост и ключ.
  Значит, регрессии в `ssh2`-специфике (алгоритмы, `shell`, `setWindow`, exit code) ловятся
  только ручным прогоном на живом хосте.
- **WS-прокси без nginx.** Прокси проверен через nginx (`test/nginx-proxy.test.ts`); случай
  «браузер подключён к приложению напрямую» тем же кодом, но отдельным тестом не закреплён.
- **Переподключение по сети.** Обрыв TCP посреди кадра, таймауты прокси и переподключение
  браузера проверены руками, не тестом.
- **Браузерный JS.** Синтаксис и паритет кадров проверяются (`node --check`, `test/frames-parity.test.ts`),
  но поведение UI — руками.
- **Пропажа питания.** `synchronous=FULL` — это аргумент, а не измерение. Проверка требует
  отдельного стенда с отключением питания; сейчас это заявка, а не факт.
- **Ретенция истории.** Логика удаления старых чанков не покрыта тестом на границе
  `WEB_SSH_SCROLLBACK_BYTES`.
