# Web SSH Client

SSH-терминал в браузере: несколько консолей, креды в БД под шифрованием, история сессий.
Главное отличие от обычного «веб-шелла» — сессии живут в отдельных процессах и переживают
перезапуск веб-слоя и его падение.

## Что уже работает (v3.0.0)

Интерфейс: рельс сессий и хостов, вкладки-консоли, xterm, мобильный drawer и панель клавиш
(Esc/Tab/^C/^D/^Z/стрелки), восстановление истории после F5. Скриншоты —
`artifacts/shots/` (десктоп 1440, телефон 390).

- **Креды в БД.** AES-256-GCM, ключ в файле вне БД; API наружу секреты не отдаёт.
- **Сессии в отдельных воркерах.** `ssh2` живёт в процессе на сессию; отключение браузера
  не рвёт терминал, перезапуск веб-слоя — тоже.
- **История на сервере.** Вывод пишется в SQLite (WAL, `synchronous=FULL`) до отправки клиенту;
  после перезагрузки страницы прокрутка восстанавливается из БД.
- **Сверка состояния.** При старте и раз в 10 с БД сверяется с живыми сокетами: сессия,
  которую унесли `SIGKILL` или перезагрузка хоста, помечается `lost`, а не висит «активной».
- **Мультиконсоль на уровне API.** Несколько сессий на пользователя, у каждой свой воркер,
  `attach` нескольких клиентов к одной сессии (телефон + ноутбук).
- **19 тестов в `node tools/verify.mjs`** — типы, крипто, кадры, REST-слой и тест на выживание
  при `SIGKILL` веб-слоя и воркера. Плюс гейтед-тест через настоящий nginx: `wss://` и кадры
  терминала проверяются на боевом конфиге прокси.

Чего ещё нет: сверки `known_hosts` (ADR-007), TOTP, ограничения частоты входов на уровне
приложения, переподключения после перезагрузки хоста через tmux (ADR-006). Деплой на хост
подготовлен целиком (`deploy/`), но ставится от root — см. `docs/deploy.md`.

## Быстрый старт

```bash
pnpm install
cp .env.example .env          # выставить WEB_SSH_ALLOW_REGISTRATION=false после первого входа
node --watch src/index.ts     # http://127.0.0.1:3000
```

Первый вход — регистрация владельца: пока в БД нет пользователей, форма регистрации открыта.

```bash
node tools/verify.mjs         # типы + тесты
node src/hub/cli.ts status    # что реально живёт: pid, сокет, статус
```

Прогон интерфейса без реальных хостов (эхо-транспорт вместо SSH):

```bash
WEB_SSH_FAKE_SESSIONS=true WEB_SSH_DATA_DIR=/tmp/wssh-demo node src/index.ts
```

Открыть `http://127.0.0.1:3000`, создать владельца, добавить хост `127.0.0.1` с любым
пользователем — консоль будет отвечать `[fake] tick N` и эхом на ввод.

## Как это устроено

```
браузер ──HTTP(REST)──► веб-слой (fastify)  ──spawn──► воркер сессии ──ssh2──► удалённый хост
   └─────WS(кадры)─────► прокси кадров ──unix-сокет──► воркер (ring + SQLite)
```

Воркер запускается `detached` и не умирает вместе с родителем. Источник правды о живости —
подключение к его Unix-сокету. Подробности, включая честные границы («хост перезагрузили —
сессия не выживет»), — `docs/ARCHITECTURE.md` и `docs/decisions.md`.
