# web-ssh-client — правила работы

Веб-клиент SSH: терминал в браузере, креды в БД под шифрованием, сессии, которые переживают
перезапуск веб-слоя и падение процесса. Читать вместе с `docs/ARCHITECTURE.md`.

## Проверки (обязательны перед коммитом)

```bash
node tools/verify.mjs        # типы + тесты, одна команда
node tools/verify.mjs 2>&1 | tee artifacts/selftest.log   # для отчёта
```

Отдельно:

```bash
pnpm typecheck               # только tsc --noEmit
node --test test/            # только тесты
node src/hub/cli.ts status   # живые сессии: pid, сокет, статус
node src/hub/cli.ts reconcile
```

Локальный запуск: `pnpm install && cp .env.example .env && node --watch src/index.ts`,
первый вход — регистрация владельца на `/`, пока в БД нет пользователей.

Реальный SSH проверяется гейтед-тестом (без переменных он пропускается, а не «проходит»):

```bash
WEB_SSH_TEST_HOST=127.0.0.1 WEB_SSH_TEST_USER=$USER WEB_SSH_TEST_KEY=~/.ssh/webssh-test \
  node --test test/real-ssh.test.ts
```

Деплой: `docs/deploy.md`. Установка требует root, поэтому агент готовит архив и команды,
а `sudo deploy/install-host.sh <архив>` выполняет владелец. Выдавать подготовленный деплой
за выполненный нельзя: пока `install-host.sh` не отработал, сервиса на хосте нет.

## Инварианты, которые нельзя ломать
1. **Секрет не покидает сервер.** Ни один API не возвращает пароль/ключ. Креды шифруются
   в `src/vault.ts`, ключ — файл вне БД. Если правка начинает возвращать секрет наружу
   (даже «для отладки») — это блокирующая ошибка.
2. **SSH живёт в воркере, не в веб-слое.** Подключение `ssh2` в HTTP-процессе вернёт старую
   болезнь: перезапуск сервиса рвёт терминалы. Соединение — только `src/hub/worker.ts`.
3. **Живость сессии проверяется подключением к сокету**, а не наличием файла сокета и не
   статусом в БД. После SIGKILL файл остаётся, а процесс уже мёртв.
4. **Вывод пишется на диск до того, как уйдёт клиенту**, пачками по 25 мс / 64 КиБ. Обещание
   «история сохранится» проверяется тестом `test/session-resilience.test.ts`, а не глазами.
5. **Схема БД меняется миграцией**, а не правкой `schema.sql` «на месте»: файл применяется
   на старте, и расхождение с существующей БД ломает запуск у того, кто обновился.
6. **Код и данные живут в разных каталогах**: `/opt/web-ssh` принадлежит root (сервис не может
   подменить себе код), `/var/lib/web-ssh` — единственное место, куда сервис пишет. Архив
   релиза собирается `deploy/make-release.sh`; каталог данных в него не попадает никогда.
7. **`KillMode=process` в юните — не деталь стиля.** `systemctl restart web-ssh` обязан
   оставлять сессии живыми; тест — открыть терминал, перезапустить сервис, увидеть, что вывод
   продолжается.

## Границы

- Реальные креды и приватные ключи в тестах и документации — нет. Тесты ходят в фейковый
  транспорт воркера (`--fake`), наружу ничего не подключается.
- Хост-ключи SSH: сейчас `ssh2` не сверяет `known_hosts` (см. `docs/decisions.md`, ADR-007) —
  это известное ограничение, а не забытая галочка. Не выдавать за сделанное.
- Секреты, OAuth, магазины расширений и чужие аккаунты не трогать.

## Стиль

- Комментарии — про причину и последствия («почему так», «что сломается иначе»), не про
  синтаксис. Русский, как в остальных проектах портфеля.
- Ошибка вместо тишины: если что-то не так — падать с внятным текстом, а не продолжать
  с полурабочим состоянием.
